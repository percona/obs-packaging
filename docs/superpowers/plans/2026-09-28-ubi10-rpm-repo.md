# UBI 10 RPM Build Repository Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the `UBI_10` RPM build repository to every OBS project that already builds for `UBI_8` and `UBI_9`, so that every package green on `UBI_9` is also green on `UBI_10` for x86_64 and aarch64.

**Architecture:** Pure packaging-config change. One repository block in `root/project.yaml` is inherited by the whole tree; the two projects that opt out of inheritance and declare their own UBI repositories (`_shared/extras`, `16/tde`) get an explicit block; prjconf blocks that exist for `RockyLinux_10` are widened to `UBI_10`; four `package.yaml` files that disable `UBI_9` also disable `UBI_10`. Nothing in `percona_obs/`, `.github/` or `root/ppg/releases/` changes.

**Tech Stack:** YAML packaging tree under `root/`, `percona-obs` CLI (`project config`, `project verify`), pytest suite in `tests/`, OBS on `obs.pg.labs.percona.com` via the `labsmain` profile.

**Spec:** `docs/superpowers/specs/2026-09-28-ubi10-rpm-repo-design.md`

## Global Constraints

- Work only in the worktree `.claude/worktrees/ubi10-repo` (branch `ubi10-repo`, based on `percona/main`). Never `cd` to the primary checkout.
- `venv` and `.profile` in the worktree are symlinks to the primary checkout's. `venv/bin/python -m percona_obs …` is the CLI. All `project config` calls below need `-P labsmain --offline`; the `labsmain` profile slices output to `UBI_*`/`ubi*`/`images` repositories, so `RockyLinux_*`, Debian and Ubuntu repos are expected to be absent from its output.
- The `UBI_10` repository block is byte-for-byte the `UBI_9` block with `9` → `10`, in the same path order (`common:deps:build`, EPEL, `RedHat:UBI-10/standard`, `RockyLinux:10/devel`), `archs: [x86_64, aarch64]`. Same rule for the opt-out projects: copy their own `UBI_9` block.
- prjconf for `UBI_10` = the three `RockyLinux_10` settings from `root/ppg/staging/subprojects.yaml` (`Prefer: selinux-policy-targeted`, `Prefer: hdf-libs`, `%__brp_check_rpaths %{nil}` macro). No `have choice` fixes up front.
- `package.yaml` rule: `UBI_10` mirrors `UBI_9`. Only the four packages with `UBI_9: false` get `UBI_10: false`. Do not copy `RockyLinux_10: false`.
- No changes under `root/ppg/releases/`, `percona_obs/`, `.github/`, `tests/`.
- Commits: `git commit -s`, no `Co-Authored-By` lines. Never `git push`, never `gh pr create`; the user does both after Task 5.
- After every task: `venv/bin/black percona_obs/ && venv/bin/pyright && venv/bin/pytest -q` must pass (369 tests at baseline; no Python changes expected, this guards the YAML through the config-merge tests).

**User decisions (already made):**
- "We need to add UBI-10 for all packages we already build for UBI-8 and UBI-9."
- "Yes devel tier should pick up UBI_10 automatically."
- `RedHat:UBI-10` on labs already matches `RedHat:UBI-8`/`UBI-9` (repo names, both archs). Done by the user 2026-09-28.
- Releases stay untouched; they pick up `UBI_10` at the next release train.
- No changes to the dev OBS instance.
- UBI 10 container images and dropping the kiwi `minimal-image` are separate later PRs.

- [ ] No package is `unresolvable`, `failed` or `broken` on `UBI_10` in the PR project.
- [ ] Every fix commit explains the OBS symptom it addresses in its message.

**Verify:** `venv/bin/python -m percona_obs -P labspr build status --repo UBI_10 ppg:staging:18 | awk '/^[├└]── /{pkg=$2} /UBI_10/ && !/succeeded|disabled|excluded/{print pkg": "$0}'` → no output (repeat for each project in the list above).

`build status` prints a tree: a `├── <package>` line, then one `│   └── UBI_10   ✔ succeeded   <version>` line per repository (status token is the third field after the repo name). The awk above carries the package name onto its repo lines.

**Steps:**

- [ ] **Step 1: Create a profile for the PR root project**

Use the PR number `N` the user reported. Copy the `labsmain` profile and change the root project:

```bash
sed 's/^rootprj: .*/rootprj: isv:percona:PR:pr-N/' .profile/labsmain.yaml > .profile/labspr.yaml
grep -n "rootprj\|apiurl\|include-repositories" .profile/labspr.yaml
```
Expected: `apiurl: https://obs.pg.labs.percona.com`, `rootprj: isv:percona:PR:pr-N`, `include-repositories` unchanged.

- [ ] **Step 2: Wait for the PR check to finish syncing and building**

The `obs-pr-check` workflow syncs the branch to `isv:percona:PR:pr-N` and polls builds (timeout 6 h). Check progress with:

```bash
venv/bin/python -m percona_obs -P labspr build status --repo UBI_10 ppg:staging:18 | grep -o 'UBI_10 .*' | awk '{print $3}' | sort | uniq -c
```
Expected while running: counts of `scheduled`/`building`/`blocked`; move on only when no package is still in one of those states across all projects listed in the acceptance criteria.

- [ ] **Step 3: Collect the non-green set**

```bash
for p in common:deps:build common:deps:runtime ppg:common:deps ppg:staging:14 ppg:staging:15 ppg:staging:16 ppg:staging:17 ppg:staging:18 ppg:staging:16:extras ppg:staging:17:extras ppg:staging:18:extras ppg:staging:16:tde; do
  echo "=== $p"
  venv/bin/python -m percona_obs -P labspr build status --repo UBI_10 $p | awk '/^[├└]── /{pkg=$2} /UBI_10/ && !/succeeded|disabled|excluded/{print pkg": "$0}'
done
```
Expected at the end of the task: no lines under any project. Each line at the start is one item to triage in Step 4.

- [ ] **Step 4: Triage each non-green package**

For a package `PKG` in project `PRJ` on arch `ARCH`, read the reason:

```bash
venv/bin/osc -A https://obs.pg.labs.percona.com results -r UBI_10 -a ARCH -v isv:percona:PR:pr-N:PRJ PKG
venv/bin/osc -A https://obs.pg.labs.percona.com buildlog isv:percona:PR:pr-N:PRJ PKG UBI_10 ARCH | tail -60
```
(`PRJ` is the colon path after the root, e.g. `ppg:staging:18`.)

Apply exactly one of these outcomes:

1. `unresolvable: nothing provides X` and `X` is provided by our own `ppg:common:deps` or `common:deps:build` on `UBI_9` but not on `UBI_10` → the provider is one of the packages given `UBI_10: false` in Task 4 or is itself non-green; fix the provider first, re-run Step 3.
2. `unresolvable: have choice for X: A B` → add `Prefer: A` (the same choice the `UBI_9`/`RockyLinux_10` blocks make when one exists, e.g. `libverto-libev`, `Lmod`, `hdf-libs`) inside a `%if "%_repository" == "UBI_10"` block of the project file that owns the `UBI_9` precedent (`root/ppg/common/deps/project.yaml` or `root/common/deps/runtime/project.yaml` for the krb5 chain, `root/ppg/staging/subprojects.yaml` for PPG-wide ones), with a one-line comment naming the package that reported it.
3. `unresolvable: nothing provides X` and `X` is a distro package present in RHEL 10 appstream/CRB but missing from `RedHat:UBI-10` and `RockyLinux:10/devel` → report to the user with the package name; the fix is on the labs mirror side (or a new dep package) and is out of this PR's scope. Do not add extra `RockyLinux:10` paths.
4. `succeeded` on `UBI_9` but the package is redundant on UBI 10 (buildlog shows the distro version being installed instead of ours, or a file conflict with a distro package) → `UBI_10: false` in that `package.yaml` with a comment in the style of `geos`/`proj`:
   ```yaml
     # UBI_10: RHEL 10 ships <pkg> in appstream, so no backport is needed there.
     UBI_10: false
   ```
5. `failed` with a compile/packaging error specific to EL10 → if it is a one-line spec/patch fix, make it and commit; otherwise report it to the user with the log excerpt and leave the package `failed` for a decision.

Commit each fix on its own:

```bash
git add <file>
git commit -s -m "<area>: <fix> for UBI_10

OBS reported '<symptom copied from osc results -v>' for <pkg> on UBI_10."
```

Ask the user to push after each batch of fixes (`git push rdias ubi10-repo`); the PR check re-syncs and rebuilds only the changed packages.
